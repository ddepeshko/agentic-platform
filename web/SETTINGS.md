# Правила коду для `web/` (Angular)

Ці правила мають пріоритет над загальними рекомендаціями в `CLAUDE.md`, якщо вони суперечать одне одному.

## Структура

```
src/app/
├── core/                ← одне на весь застосунок: API-клієнт, контракти, пізніше авторизація
├── shared/              ← UI-компоненти, потрібні кільком фічам
└── features/<назва>/    ← сторінки; кожна вантажиться ліниво через роутер
```

- Верхній рівень `app/` групуємо за фічами, а не за типом коду.
- Усередині фічі: сторінка (`<назва>.component.*`) у корені фічі, дочірні компоненти в `components/` (кожен у своїй папці), сервіси в `services/`, інтерфейси в `models/` (з barrel `index.ts`).

```
features/playground/
├── playground.component.ts / .html / .scss
├── components/
│   ├── chat-composer/
│   ├── settings-panel/
│   └── conversation-inspector/
├── services/chat-session.service.ts
└── models/
    ├── chat-settings.ts
    └── index.ts
```
- `core` нічого не імпортує з `features`; фічі не імпортують одна одну.
- Імпорти між шарами через аліаси `@core/*`, `@shared/*` (`tsconfig.json`).
- Нова сторінка = папка в `features/` + рядок з `loadComponent` в `app.routes.ts`.

## Іменування

- Кожен компонент у своїй папці.
- Компоненти: `chat-composer.component.ts` / `.html` / `.scss`, клас `ChatComposerComponent`.
- Сервіси: `agent-api.service.ts`, клас `AgentApiService`.
- Schematics в `angular.json` налаштовані так само, тож `ng g c` і `ng g s` одразу дають потрібні імена.

## Типи

- `interface` замість `type`.
- Кожен інтерфейс у своєму файлі, експорт через barrel (`index.ts`).
- `type` лише там, де інтерфейс неможливий: union або синонім типу з бібліотеки.

## UI

- Компоненти з Angular Material.
- Кольори й шрифти з токенів теми `--mat-sys-*`, без власних кольорів.
- Без `aria-*` атрибутів у шаблонах.

## Загальне

- Код має виглядати як написаний людиною: мінімум коментарів (лише «чому», не «що»), без зайвих абстракцій і бойлерплейту.
- Обробка помилок лише для підключення до моделі та відповіді агента; решту не обгортаємо в try/catch.
- Тести поки не пишемо (schematics не генерують `.spec.ts`).
- Без Zod.
