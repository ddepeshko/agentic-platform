# PROGRESS

## Структура репозиторію

```
agent-platform/
├── api/        NestJS: увесь бекенд (LLM, агенти, тули, пізніше БД і MCP-клієнт)
├── web/        Angular: UI (playground, пізніше CRUD агентів і адмінка)
├── docs/       опис продукту: еталонні агенти, рішення
├── evals/      окремий пакет (модуль 8): runner + датасети, б'є в HTTP API як у «чорну скриньку»
└── *.md        HANDOFF, REQUIREMENTS, PROGRESS, CLAUDE; package.json — лише скрипти-обгортки
```

- `docs/` і `evals/` лишаються в корені: вони про продукт і про перевірку всієї платформи, а не про код одного застосунку. Evals не залежать від Nest, тож переписування `api/` або зміна моделі чи промпта не ламають датасети.
- Корінних `src/core|platform|domain` з `HANDOFF.md` більше немає; діє структура вище.

### Цільова архітектура (куди рухаємось)

**Агент — це дані, тул — це код.** Платформа не знає про «погоду»: агенти створюються з фронта, а не додаються в репозиторій.

| Що | Де живе | Хто створює | Модуль |
|---|---|---|---|
| Агент: назва, опис, system prompt, модель, тули, права | MySQL | користувач з UI | 4, 12 |
| Опис тула: назва, опис, JSON-схема | реєстр тулів; для MCP — з самого сервера | платформа | 2 |
| Реалізація тула | вбудовані тули в `api/` або MCP-сервери | розробник | 2–3 |

```
api/src/modules/
├── agents/     CRUD агентів (БД)
├── runtime/    загальний agent loop: агент з БД за ID → його тули → цикл
├── tools/      реєстр тулів: вбудовані + з MCP (+ можливо декларативні HTTP-тули)
└── mcp/        клієнт до підключених MCP-серверів
mcp-servers/    наші MCP-сервери (weather, currency, telegram)
web/src/app/features/
├── agents/     список, створення, редагування агента
└── playground/ чат з обраним агентом
```

- Три агенти з `docs/AGENTS.md` — **еталонні приклади**, що покривають три рівні ризику (читає → пише у свою БД → діє у світі). У БД потрапляють як seed (`system`), їхні evals у репозиторії — регресія самої платформи.
- З UI можна: створити агента з готових тулів, підключити MCP-сервер за URL, (можливо) описати простий HTTP-тул. Не можна: генерувати чи завантажувати код тулів / MCP-серверів (див. `REQUIREMENTS.md`, п. 6).
- Зараз погоду зашито в платформу (`AgentService` імпортує `WEATHER_SYSTEM_PROMPT` і `weatherTools`). Це свідомо для уроків 1.x; розв'язуємо поступово: модуль 2 (реєстр тулів, MCP) → модуль 4 (агент з БД, `agentId`) → модуль 12 (UI агентів). Наперед абстракцій не будуємо.
